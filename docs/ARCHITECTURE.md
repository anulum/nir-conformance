# Repository architecture

## Current executable tooling

Metadata, source-provenance, workflow, dependency-alignment, documentation, inventory and preflight controls inspect declared local scopes. Native bootstrap checks selected executable and licence files. Received metadata cannot select policy or grant conformance. Foundation qualification is in progress.

## Intended conformance boundaries

| Component | Responsibility | Required evidence |
| --- | --- | --- |
| Catalogue and suite | Fix the entire declared primitive, lane and corner population | Actual pinned NIR and framework source, parameters, graph/input and numerical profile |
| References | Qualify expected behaviour through independent paths | Separate actual source lineage, executions, complete traces and common assumptions |
| Lanes | Retain import, export and round-trip transformations | Actual installed execution contracts, intermediate graphs and source-bound receipts |
| Comparison | Evaluate every selected observable under its declared realisation | Units, event counts/order, solver and explicit tolerance or exact-discrete rule |
| Findings | Locate differences without exaggerating reduction | Original graph/input/timing witness and actual proved search scope |
| Evidence | Produce a whole native candidate and separate verification | Complete declared support and uncovered inventory, shared evidence and independent consumer |

The prospective certificate has thirteen required fields: schema_id, claims, source_ref, environment_ref, framework, nir_version, suite, numeric_class, executor, cases, declared_supported_primitives, uncovered_primitives and overall. This declaration is not registered or qualified support.

Three prospective public operations are run, verify and matrix. Suite qualification, import, export, roundtrip, report and verification are internal steps of those operations. None is installed. The user spelling round-trip maps explicitly to the native lane round_trip.

Every suite binds the actual versioned serializable catalogue and full required case population. Helpers and internal classes cannot inflate primitive support. Each framework version and numerical realisation has its own scope. The suite covers shapes, connectivity, signed/bias arithmetic, convolution and pooling conventions, state/current dynamics, delay, threshold equality, resets and all declared corners.

References require at least two genuinely independent actual paths. An analytic derivation can guide one reference but is not an execution receipt. Two traces produced by the same importer or generator do not establish independence. Numerical profiles bind timestep, solver, held-input intervals, initial state, reset order and threshold predicate; an allowed discretization difference must remain visible.

State, weight, input and time comparisons each use an earlier selected absolute/relative protocol with units, reference magnitude and full coordinate reduction. A time tolerance cannot forgive a missing spike. Exact discrete identity requires zero discrepancy. Complete source and arithmetic qualification remains separate from shape-compatible tolerance parameters.

Import retains original graph and imported runtime observations. Export retains the framework-native source and exported semantics. Round-trip retains both transformations and executions so cancelling errors cannot become evidence of preservation.

Per-case verdicts are conformant, divergent, unsupported or inconclusive. Declared unsupported support is not a pass; missing goldens or execution remain unavailable or inconclusive. Native cases require two genuine golden references, so missing references may prevent certificate construction. Never duplicate a trace merely to satisfy its shape.

Overall conformance concerns the exact declared scope and whole required population. An all-unsupported or unexecuted campaign cannot supply a positive result. Preserve uncovered primitives and all missing cells. A located counterexample is globally minimal only within an actually proved reduction scope.

NIR Conformance retains its independent semantic oracle; Divergence Harness owns execution and reduction. The project's own bridge is tested first under the same rules. Studio groups only compatible NIR, suite, numerical and executor versions and renders existing findings. Shared signatures do not establish conformance or current eligibility.
